# motionshorts — faceless 3D explainer reels (instructions for any coding agent)

Vertical (1080×1920, 30 fps) explainer shorts made entirely in code: Remotion + Three.js
(fast) or Blender/EEVEE (photoreal, slower), TTS voiceover, word-synced captions, seamless
loops. Works with Claude Code, Codex (ChatGPT), Cursor, Gemini CLI — any agent that can run
shell commands on this machine. A chat without a terminal (plain ChatGPT/Claude web) can only
write scripts and storyboards; rendering needs the local tools.

## First thing in every session
1. `scripts/doctor.sh` — what is installed. If anything is MISSING, run `scripts/setup.sh`.
2. Read its `VOICE:` line:
   - `chatterbox` → local voice (default engine).
   - `openai` → `--engine openai` (OPENAI_API_KEY is set).
   - `ask` → **ask the user** which to use: (a) give an OpenAI API key (`export OPENAI_API_KEY=…`,
     best quality without a big install, a few cents per video), (b) install the local model
     with `scripts/setup.sh --local-voice` (~3 GB, needs 16 GB RAM), or (c) free `--engine edge`
     (more robotic). Never guess; never put keys in files or the repo.

## Workflow (skills = step-by-step playbooks, read them before working)
1. `.claude/skills/reel-director/SKILL.md` — brief → research → 5 hooks ★ → script ★ → voice → storyboard
   (references in `.claude/skills/reel-director/references/`)
2. `.claude/skills/reel-build/SKILL.md` — storyboard → `src/videos/<slug>/` → stills ★ → render → QA.
   Its "Blender pipeline" section covers the photoreal variant (draft ★ → final).
3. Remotion API questions: `.claude/skills/remotion-best-practices/SKILL.md`.

★ = stop and let the user decide. Answer in the user's language.

## Layout
- `videos/<slug>/` — director files: brief.md, script.txt, storyboard.md
- `public/<slug>/` — vo.mp3 + words.json (from `scripts/voice.py`)
- `src/lib/` — shared component library (API table in the reel-build skill)
- `src/videos/<slug>/` — the video code; registered in `src/Root.tsx`
- `blender/` — Blender pipeline: `common.py` (cues, scene, materials, camera), `models/` (recorder,
  airliner, liner), one script per reel (`blackbox.py`, `titanic.py`)
- `out/` — renders, stills, QA sheets (gitignored)

## Commands
- Setup / check: `scripts/setup.sh [--local-voice]`, `scripts/doctor.sh`
- Voice: `.venv-tts/bin/python scripts/voice.py <slug> [--engine chatterbox|openai|edge|file]`
  (chatterbox: `--ref voices/refs/<name>.wav` for another voice; openai: `--voice onyx|ash|echo`;
  edge: `--voice en-US-AndrewNeural`, German `de-DE-ConradNeural`; file: `--audio my_take.m4a`)
- Re-time words only: `.venv-tts/bin/python scripts/voice.py <slug> --resnap`
- Sound library: `.venv-tts/bin/python scripts/sfx.py` → `public/sfx/*.wav`, `public/music/*.wav`
- Preview: `npm run dev` · Typecheck: `npx tsc --noEmit`
- Stills: `scripts/stills.sh <slug> 0 120 300 …` → `out/stills/<slug>/sheet.jpg`
- Render: `npx remotion render <slug> out/<slug>.mp4 --concurrency=3`
- QA: `scripts/qa.sh out/<slug>.mp4`
- Blender: `blender -b -P blender/<reel>.py -- --stills 0,120 --res 30 --samples 8` (look-dev),
  `-- --render --draft` (3-min preview frames), `-- --render` (final frames)

## Rules
- **Memory:** on a 16 GB machine never run local TTS (Chatterbox) and a render at the same time;
  keep ≥ 10 GB disk free. voice.py aborts itself when memory runs low.
- Run long jobs (renders, TTS, Blender) in the background and check back; don't block.
- Review every render yourself before showing it (reel-build → Review loop). Be strict and honest
  about what still looks weak.
- Accuracy beats drama: every number in a script needs a source or a calculation.
- Licences: Remotion is free for individuals and companies of up to 3 people (bigger teams need a
  company licence, remotion.dev/license). Textures/HDRIs in `public/textures` are CC0 (Poly Haven).
  Sounds and music are generated by `scripts/sfx.py` (no samples). Only clone voices you have the
  rights to.
